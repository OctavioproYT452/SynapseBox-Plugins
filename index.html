Crear plugins para SynapseBox

Guía para escribir plugins en Node.js que cambian iconos, imágenes, funciones y comportamiento. Requiere SynapseBox 2.15.0 o superior.

Introducción

Un plugin es una carpeta con código. El administrador puede activarlo y desactivarlo al instante desde Admin → Plugins, sin reiniciar el servidor. Un plugin puede tener tres partes, todas opcionales:

ArchivoDónde se ejecutaPara qué
server.jsNode.js (servidor)Rutas, middleware, reemplazar archivos, base de datos, tareas, eventos.
client.jsNavegadorCambiar la interfaz, añadir botones, atajos, avisos…
style.cssNavegadorColores, tamaños, ocultar o mover elementos.
Importante: el código de server.js se ejecuta con los mismos permisos que SynapseBox (puede leer archivos, la base de datos y abrir conexiones). Por eso solo los administradores gestionan plugins.

Estructura de un plugin

mi-plugin/
├── plugin.json     ← obligatorio
├── server.js       ← opcional
├── client.js       ← opcional
├── style.css       ← opcional
└── images/         ← portada y capturas (1 a 5 imágenes)

Para probarlo en local, copia la carpeta a data/plugins/mi-plugin/ (el nombre de la carpeta debe ser el id), entra en Admin → Plugins → Instalados y actívalo.

plugin.json

{
  "id": "mi-plugin",
  "title": "Mi plugin",
  "version": "1.0.0",
  "category": "Utilidades",
  "author": "tu-usuario",
  "description": "Qué hace, en una o dos frases.",
  "images": ["images/imagen-1.png"],
  "server": "server.js",
  "client": "client.js",
  "style": "style.css",
  "files": ["server.js", "client.js", "style.css"]
}
CampoNotas
idObligatorio. Minúsculas, números y guiones (2-40 caracteres). Debe coincidir con la carpeta.
title, description, version, authorSe muestran en el panel. La versión sigue el formato 1.0.0.
categoryAgrupa el plugin en el repositorio (Apariencia, Utilidades, Seguridad…).
imagesDe 1 a 5; la primera es la portada. PNG, JPG, GIF, WebP o SVG.
server, client, styleNombres de los archivos que se cargan. Omite los que no uses.
Si subes el plugin desde el panel, SynapseBox genera el plugin.json por ti con los datos del formulario. Detecta server.js, client.js y style.css por su nombre.

API del servidor (server.js)

server.js exporta una función, o un objeto con activate y deactivate. Ambos reciben api.

// Forma corta
module.exports = api => { api.log("hola"); };

// Forma completa
module.exports = {
  async activate(api) { /* se ejecuta al activar */ },
  async deactivate(api) { /* se ejecuta al desactivar: limpia temporizadores, etc. */ }
};
PropiedadDescripción
api.use(fn)Middleware de Express para todas las peticiones. Va antes que las rutas de SynapseBox: puedes leerlas, cambiarlas o cortarlas.
api.get / post / put / delete(ruta, fn)Rutas propias. Si usas una ruta que ya existe, la tuya la reemplaza.
api.serveFile(url, archivo)Responde una URL con un archivo de tu plugin. Sirve para cambiar iconos e imágenes (/favicon.svg, /icons.svg…).
api.serveDir(url, carpeta)Publica una carpeta de tu plugin bajo una URL.
api.router, api.app, api.expressAcceso directo al router del plugin, a la app de Express y al módulo express.
api.on(evento, fn) / api.emit(evento, datos)Eventos. Los de SynapseBox: server:start y plugin:enabled. Puedes crear los tuyos.
api.transformHtml(fn)fn(html, {url, user}) devuelve el HTML modificado de cualquier página antes de enviarla.
api.inject.head / api.inject.bodyListas de fragmentos HTML que se añaden a todas las páginas.
api.data.read(nombre, defecto) / api.data.write(nombre, valor)Almacenamiento JSON propio en data/plugin-data/<id>/.
api.dbBase de datos de SynapseBox: get, all, run (SQLite).
api.core("services/auth")Carga cualquier módulo interno de src/.
api.settings, api.config, api.utilsAjustes globales, rutas y utilidades del servidor.
api.manifest, api.dir, api.dataDir, api.log()Tu plugin.json, tu carpeta, tu carpeta de datos y un console.log con prefijo.

En las rutas, req.user es el usuario con sesión (o null) y req.user.is_admin indica si es administrador.

SDK del cliente (client.js y style.css)

Tu style.css y client.js se añaden a todas las páginas HTML mientras el plugin esté activo. Antes de tu script se carga window.SynapseBox:

FunciónDescripción
SynapseBox.pageNombre de la página: panel, index, themes, admin/index…
SynapseBox.ready(fn)Ejecuta fn cuando el DOM está listo.
SynapseBox.api(url, cuerpo?, método?)fetch con JSON; lanza Error si falla. Con FormData envía archivos.
SynapseBox.css(texto)Inserta CSS en la página.
SynapseBox.html(selector, html)Cambia el contenido de un elemento.
SynapseBox.toast(mensaje, esError?)Aviso emergente.
SynapseBox.session()Datos de la sesión actual.
SynapseBox.on / emitEventos del navegador; ready se emite con el nombre de la página.
Dentro del navegador tienes el DOM completo: puedes cambiar iconos (<svg><use href="/icons.svg#…">), imágenes, textos, ocultar botones o añadir otros nuevos. Por la política de seguridad (CSP) los scripts deben ser archivos de tu plugin, no código inline.

Recetas

Cambiar un icono o una imagen

// server.js
module.exports = api => {
  api.serveFile("/favicon.svg", "mi-icono.svg");
  api.serveFile("/apple-touch-icon.png", "icono.png");
};

Añadir una ruta

module.exports = api => {
  api.get("/api/plugins/mi-plugin/hora", (req, res) => {
    if (!req.user) return res.status(401).json({ error: "No autorizado" });
    res.json({ hora: new Date().toISOString() });
  });
};

Cambiar el comportamiento de una ruta existente

module.exports = api => {
  api.use((req, res, next) => {
    if (req.method === "POST" && req.path === "/api/login") api.log("intento de login");
    next(); // sin next() la petición se corta aquí
  });
};

Modificar el HTML de una página

module.exports = api => {
  api.transformHtml((html, { url }) => html.replace("<title>", "<title>🧩 "));
};

Guardar datos

module.exports = api => {
  api.post("/api/plugins/contador/sumar", (req, res) => {
    const n = (api.data.read("contador", { n: 0 }).n) + 1;
    api.data.write("contador", { n });
    res.json({ n });
  });
};

Usar la base de datos y módulos internos

module.exports = api => {
  api.get("/api/plugins/mi-plugin/usuarios", (req, res) => {
    if (!req.user?.is_admin) return res.status(403).json({ error: "Solo administradores" });
    res.json(api.db.all("SELECT username FROM users ORDER BY username"));
  });
};

Tarea periódica (limpiar al desactivar)

let timer;
module.exports = {
  activate(api) { timer = setInterval(() => api.log("tick"), 60000); },
  deactivate() { clearInterval(timer); }
};

Cliente: botón nuevo y estilo

// client.js
SynapseBox.ready(() => {
  if (SynapseBox.page !== "panel") return;
  const b = document.createElement("button");
  b.className = "btn"; b.textContent = "Saludar";
  b.onclick = () => SynapseBox.toast("¡Hola!");
  document.body.append(b);
});

Ciclo de vida

  • Activar: se carga server.js (sin caché), se llama a activate(api) y desde ese momento sus rutas, client.js y style.css funcionan.
  • Desactivar: se llama a deactivate(api), se quitan sus rutas y eventos y deja de inyectarse en las páginas.
  • Al arrancar el servidor: se cargan los plugins que estaban activos.
  • Actualizar: descargar de nuevo desde el repositorio reemplaza los archivos; si estaba activo se recarga solo.
  • Si un plugin lanza un error al cargar, se muestra en la consola del servidor y el resto sigue funcionando.

Publicar tu plugin

En Admin → Plugins → Subir plugin rellena todos los campos obligatorios:

  • Título y descripción (mínimo 10 caracteres).
  • Categoría: se crea una carpeta con ese nombre.
  • Imágenes: de 1 a 5 (obligatoria al menos una; la primera es la portada).
  • Archivo(s) del plugin: al menos uno.
  • Versión (opcional, por defecto 1.0.0).

Node ejecuta git, crea una rama plugin/<id>-<versión>-… y abre un pull request directamente en SynapseBox-Puglins, sin forks. Un mantenedor lo revisa y lo fusiona.

Hace falta una cuenta con permiso de escritura en el repositorio. GitHub no permite crear ramas ni pull requests sin autenticarse. Dos opciones: (1) «Vincular GitHub» en el panel (código de dispositivo, sin claves en archivos; necesita PLUGINS_GITHUB_CLIENT_ID y que la cuenta sea colaboradora), o (2) PLUGINS_GITHUB_TOKEN en .env con un token fine-grained solo para este repositorio (Contents y Pull requests: Read and write); con token se hace push directo. PLUGINS_REPO=usuario/repositorio cambia el repositorio.

Para actualizar un plugin, súbelo con el mismo título y una versión mayor: se reemplaza su carpeta.

Estructura del repositorio

SynapseBox-Puglins/
└── Utilidades/                 ← categoría
    └── reloj-en-panel/         ← id del plugin
        ├── plugin.json         ← versión, título, descripción, imágenes…
        ├── images/
        │   └── imagen-1.svg
        └── client.js           ← archivos del plugin

El panel lee este árbol de GitHub, muestra las categorías con sus imágenes y descarga la carpeta del plugin a data/plugins/<id>/.

Seguridad

  • Lee el código de un plugin antes de activarlo: tiene acceso total al servidor.
  • Comprueba siempre req.user y req.user.is_admin en tus rutas.
  • Nunca confíes en req.body ni req.query: valida y limita lo que recibes.
  • No guardes secretos en el repositorio; usa api.data o variables de entorno.
  • SynapseBox nunca sirve tu server.js al navegador. Solo se sirven los archivos de tu plugin con extensiones permitidas: js, css, html, json, svg, png, jpg, gif, webp, ico, txt, md y fuentes.
  • Límites al subir: 5 MB por archivo, 5 imágenes y 20 archivos.

Buenas prácticas

  • Usa rutas con prefijo propio: /api/plugins/<id>/….
  • Limpia temporizadores y conexiones en deactivate.
  • Si reemplazas una ruta existente, ten claro qué rompes: tu plugin va antes que el código original.
  • Usa las variables CSS del tema (var(--card), var(--accent), var(--text)…) para que tu interfaz respete los temas.
  • Sube la versión en plugin.json cada vez que publiques cambios.
  • Empieza por el plugin Hola plugin (categoría Desarrollo): es una plantilla mínima.
